# 明日方舟资源与资料工作台 · 使用指南

Windows x64 便携程序入口为 `ArknightsUnpacker.exe`。保留同目录的 `_internal` 文件夹，双击程序即可运行，无需安装 Python。0.1.1 起，扫描、解析及查看状态保存在程序旁的 `data/`；移动时一并带走该文件夹即可保留历史。测试覆盖和已知缺口见 [验收摘要](ACCEPTANCE.md)。

## 第一次使用

1. 将程序文件夹解压到普通可写位置，启动 `ArknightsUnpacker.exe`。
2. 0.1.2 起默认输出为 EXE 同目录的 `exports/`，启动时不存在会自动创建，无需先手选目录。也可在“设置”中自定义输出目录；输出不得位于游戏目录内。可选择图片、文本／数据、音频和 Spine 资源，以及 PNG、HTML、JSON、TXT 资料格式。
3. 点击“选择目录…”，选择游戏根目录、`Arknights_Data`，或识别到的初始／热更资源根，再点“扫描 / 检查更新”。缺少另一层时只能覆盖已选择的资源范围。
4. 在“资源浏览”定位文件；在“干员资料”或“模组更新”点击“解析核心数据”，等待任务结束，再选择条目查看资料或导出。

游戏目录只读。程序不会移动游戏文件、替换游戏资源、读取账号或存档，也不需要先启动游戏。

再次启动会读取上次扫描、解析结果和变化记录，恢复所查看的干员／模组、页签及筛选，无需重新解析。顶部显示已保存结果的时间与版本；点击“扫描 / 检查更新”读取当前文件，与最后完整扫描比较。“解析核心数据”更新核心资料，并与保存的完整数据基线比较。源游戏盘暂时离线时，已保存资料仍可查看；解包仍需原文件可访问。

工作台统一使用浅色，列表、下拉菜单及弹窗不混入 Windows 深色控件。“资料主题”只影响导出的资料长图。

## 浏览资源与最近更新

“资源浏览”左侧是目录树，中间可按名称、路径或用途搜索，右侧显示路径、来源及诊断。工具栏可切换：

- **原始文件 · 全部来源**：浏览实际物理文件，适合有意提取历史底包。
- **当前生效资源**：按当前清单解释资源来源；缺失、旧底包、可选资源与未确认覆盖会保留状态。未安装的热更资源不会被无提示地当成旧底包。

“仅 .ab”只筛选界面中的文件显示，大小写不敏感，不会阻止后台发现匿名 `.bin` 或 `.idx` 核心数据。“包含子目录”控制当前目录列表是否递归显示。选中多行后可加入解包队列；目录右键可选择目录资源。双击支持的包或点击“查看内部对象／预览”可检查对象并选择提取。

顶部“最近”默认 24 小时，可调整；“更新记录”可查看最近写入、相对文件基线变化及两者组合。修改时间来自本机文件系统，首次观测时间来自本工具扫描；均不是服务器发布时间。首次扫描建立基线，不能确认本次新增干员。严格校验会重新计算资源摘要，耗时更长；部分扫描和取消不会冒充完整基线。

“更新记录”默认显示最近写入或基线变化的并集，保留旧时间戳的更改也能出现。可搜索路径／用途、只看 AB、排序，用 Ctrl／Shift 多选或“全选当前结果”。点击“导出所选包内图片”批量提取原始像素 PNG，该操作独立使用图片自动解包；“解包所选文件…”沿用设置中的资源类型和方式。已删除条目不可导出。

## 解包任务

在“设置”中选择资源类型与自动／原始导出方式，选中文件后点击“将所选加入解包队列”。“导出任务”显示状态与诊断，可取消当前任务、重试失败任务、点击“预览任务产物”重新查看已生成的资料，或打开输出目录。关闭程序时如有任务，程序会先请求取消并等待工作进程结束。

每次解包创建独立 `extract-时间-任务ID` 批次。单图包的 PNG 直接放批次根目录，多图包才创建源包子目录；只选一张图片也平铺。自动整包导图中，经引用、全幅尺寸和像素一致性确认的 Texture／Sprite 同图只导出一次；显式选择对象时尊重选择。Spine 保留整组相对目录，文本、音频及原始对象保持各自分组。同名使用对象 ID 和额外序号避免覆盖。`extraction-result.json` 保存输出、错误及跳过原因，后续任务不会覆盖旧批次。损坏包或不支持对象可单独失败。

游戏图片保存解码后的原始像素；Sprite 保留自身裁切尺寸，不被资料排版宽度或预览缩放重采样。对象预览可缩放，点击“保存原图…”复制原文件，保留像素、透明度及元数据；已存在目标不会被覆盖。RGB 与明确引用的 Alpha 合并时保持 RGB 尺寸，仅对齐遮罩。

任务历史自动保留。重启后，未结束的任务显示“已中断”，不会自动执行；在“导出任务”选择原任务后可手动重试，或重新打开已经生成的产物。“暂停队列”只阻止开始后续任务，当前任务继续到结束；中断当前任务请点“取消”。

解包恢复依据该任务自己的完成事件、结果清单与仍然存在的产物，只继续未完成来源／对象；崩溃中途单独写出的文件不等于整个对象完成。无法确认完整性的 Spine 组会作为未完成组重新处理，旧文件保留。恢复历史报告前需先从原安装加载对应的数据快照；入队及实际执行时都会核对安装与快照，来源不同会提示重新选择导出。报告取消后，已成功生成的产物与部分结果清单会保留；快照内容未加载时，既有 PNG／HTML 仍可从任务页重新查看。

图片、文本、Spine、音频的支持以对象实际解码结果为准。音频无法转换为可播放格式时可能保留 `.audio` 源文件并附诊断；不得将源文件后缀改为 WAV 后宣称可播放。Spine 可能仅保留原始组成文件，完整贴图组、透明通道合并和可用性须看本次结果。

USM 视频在**自动模式**下通过 WannaCRI 分离视频／音频流，本机样本生成 IVF 视频和 SFA 音频；原始模式才复制 `.usm` 源文件。程序如在系统 `PATH` 找到可选的 `ffmpeg`，会复制视频流、将音频转换为 AAC 并封装为 MKV；如找到 `ffprobe`，也会记录流探测结果。未找到 FFmpeg 时仍保留分离后的原始流，并在 `.media.json` 记录转换能力缺失；封装失败也保留原始流及诊断。此包不附 FFmpeg／FFprobe，可自行安装后将其目录加入 `PATH`，它们不是程序启动或 USM 分流的前置条件。本机样本已通过 FFprobe 流核对及 FFmpeg 前一秒音视频实际解码；这不代表全部视频均已完整播放验收，具体覆盖见 M9／引擎验收记录。

## 干员、模组与新增识别

先解析当前核心数据，然后可按名称或稳定 ID 搜索资料。静态面板默认最高精英／等级、满潜与满信赖，单名干员可选择一个模组；不会同时叠加多个模组。资料包括属性及加成来源、潜能、天赋、技能、后勤和模组，缺失或未解析字段会附诊断，不能把“未解析”理解为“无技能”。这是本地数据资料导出，未覆盖的运行时或游戏内效果不据此推定。

首次解析没有可比较的历史基线，条目为历史未知。要识别真正的本次新增／修改：

1. 在一次完整解析后使用“导出当前数据快照…”留存基线。
2. 游戏更新后重新扫描并解析，选择“资料对照”中的完整历史快照，点击“与选中快照比较”；也可“导入历史基线…”选择本工具先前导出的同服 JSON 快照。
3. 检查“只看新增／变化”或“只看新增”列表，再点击“一键导出本次新增”。不完整、不同服或不可比较快照会产生诊断，不能确认新增。

“设置 → 数据区服声明”默认 `unknown`（未知）。区服未知但两份快照来自同一安装位置时，允许比较本地内容，界面会警告不能据此确认服务器发布；跨来源且区服未知时拒绝认定新增／变更。确认当前数据和导入基线都属于简体中文／国服后，可主动选择 `zh_CN`（用户声明），保存后重新解析当前数据，再导入或比较历史快照。该选项是用户提供的来源声明，不是程序自动验证区服；已明确不同服的数据仍不可比较。

文件最近写入、资源版本变化和业务实体新增是三种不同信息。新增 ID 只代表数据中新出现；尚未确认可获取的角色不代表已正式开放。手动选择现有干员和模组始终可以导出，不必伪造历史基线。

当前 PC `building_data` 有五个新增根字段，其语义尚未解析，程序保留未知字段证据和原始来源；已知结构中的干员后勤等资料可以解出。该限制不能被理解为整张后勤表不可解，也不能据此把未知字段补成“无效果”。

## PNG 和离线 HTML

在设置中选择格式、资料 PNG 画布宽度、字号与主题，随后点击“导出选中资料”。画布宽度用于新生成的资料长图，与游戏原图无关。多份资料生成索引和 manifest；长图可分页。PNG、HTML、JSON 和 TXT 共用同一报告数据，来源、版本和诊断随报告保留，批次不覆盖历史报告。

也可先点击“预览所选资料”：程序将资料写入应用数据目录的 `previews/` 缓存，并显示 PNG 分页、上一页／下一页、缩放、适应宽度及滚动查看。预览会生成 PNG；其他格式沿用当前设置。确认后点击“导出所选到输出目录”正式保存，预览缓存不会成为已保存的输出目录。正式导出后同样显示产物窗口；关闭窗口后，可在“导出任务”选中任务，点击“预览任务产物”重新打开仍存在的产物。

HTML 为单文件离线资料页。产物窗口选择 HTML 后，由用户点击“在浏览器中打开”，也可双击文件使用 Edge、Chrome 等浏览器打开；程序不会仅因预览或导出完成就自动打开浏览器。页面内容、样式、脚本和可用图片随文件自带，不请求网络资源或联网加载 PRTS。批量 `index.html` 用于跳转同批报告；移动批次时保留其相对目录。

0.1.3 使用 HTML 模板 2.0.0，参考 PRTS 现行 `skin-arknights` 的黑色顶栏、白色资料面板、青色分区与右侧资料目录。没有附带本地肖像时不显示空白占位。页面不是 PRTS 官方页面，也不通过在线站点补齐未解析字段。

- 技能选择位于技能正文上方；切换后自动定位到相应正文并显示状态反馈。
- 模组按实际模组选择；同一条目包含简介、全部等级、属性和天赋，不把这些子块列成独立模组。等级可选 1／2／3／全部，默认显示该模组最高等级。
- 搜索显示命中数、高亮与无结果提示；清除后恢复搜索前的技能／模组选择。
- 展开／收起资料区块时保留技能、模组与等级选项，并显示操作反馈。
- “打印”按钮或 Ctrl+P 均打印完整内容；打印结束后恢复原来的筛选与折叠状态。
- 禁用 JavaScript 时仍展示全部正文，隐藏需要脚本的互动栏。

已导出的 HTML 是静态快照，升级程序后需重新导出才能使用新布局，旧报告不会被覆盖。旧 PNG／JSON 仍可读取，不作迁改。各版本的真实浏览器、窄屏及打印验证范围见验收摘要。

## 数据保留、升级与诊断

预览窗口的缩放百分比只控制显示。“保存当前原始 PNG…”复制当前页原始 PNG，其尺寸仍为生成时的资料画布尺寸。

0.1.2 起默认输出目录：EXE 同目录的 `exports/`；源码运行时为项目根的 `exports/`，启动时不存在会自动创建。它不随启动工作目录或显式 `--data-dir` 改变，也不写入 `_internal`。例如安装于 `D:\Tools\ArknightsUnpacker` 时，默认输出为 `D:\Tools\ArknightsUnpacker\exports`。可在设置中或通过 `--output-dir` 指定其他输出目录；已有文件与历史批次保留。

默认应用数据目录：EXE 同目录的 `data/`；源码运行时为源码根的 `data/`，不随启动工作目录改变。“设置 → 打开数据目录”可进入，显式 `--data-dir` 只改变这项数据目录，不改变输出默认位置。主要内容包括：

| 内容 | 用途 |
| --- | --- |
| `settings.json` | 游戏／输出路径、区服、筛选、页签及上次所选资料 |
| `catalog.sqlite3` | 扫描、解析、安装信息和上次准确的文件／实体比较结果 |
| `catalog.sqlite3.v*-backup-*.sqlite` | 数据库升级前备份 |
| `jobs/<任务 ID>/` | 隔离工作进程请求、结果、`events.jsonl`、`worker.log` 及必要时的 `diagnostics.log` |
| `queue/` | GUI 任务历史、白名单恢复请求、检查点和已生成产物路径 |
| `preview/` | 可重建的资源对象预览缓存 |
| `previews/` | “预览所选资料”生成的可重建报告缓存 |

首次从 0.1.0 升级且程序旁尚无已有数据时，非覆盖迁入旧 `%LOCALAPPDATA%\ArknightsUnpacker` 的配置、数据库和任务历史；旧位置原文件保留，可重建缓存不迁入。中断迁入后可继续，已存在的新数据不被覆盖。

旧版配置中仍使用默认 `Documents/ArknightsExports` 时，自动改用程序旁 `exports/`；其他自定义输出路径保留。只更新保存位置，不移动或删除旧目录内的导出文件，需要时仍可从旧位置读取。

用户输出、导出基线和历史报告不会自动清理。升级到新程序目录时，先退出程序，再复制整个 `data/` 到新目录旁；默认输出也需一并保留 `exports/`。不要用空目录覆盖原数据。迁移前备份数据和输出；SQLite 存在 `-wal`、`-shm` 时也应一起保留。不保证跨未知数据版本兼容。目录不可写时显示实际路径错误，可把程序移到可写位置；数据目录可用 `--data-dir` 调整，输出目录可用 `--output-dir` 调整，两者独立，不会静默改存临时目录。

发生错误时先看“导出任务”的诊断，以及对应 `worker.log`、`diagnostics.log`、`result.json`、`extraction-result.json` 和报告 manifest。保留程序版本、发生时间、选中资源的相对路径与错误文本；分享日志前检查其中的本机绝对路径。解码失败可能来自游戏格式／schema 变化、资源未安装、版本不一致或损坏文件，不能凭一次失败认定游戏缺文件。启动错误与运行时异常日志的位置以实际启动提示和 M9 验收记录为准。需隔离试用数据时可从终端启动 `ArknightsUnpacker.exe --data-dir <独立数据目录>`，并可用 `--game-root`、`--output-dir` 指定此次输入／输出。

## 从源码运行与重建

源码运行与便携程序运行属于不同验证环境。工程使用 Python 3.12 x64、uv 锁定依赖和 PowerShell 7：

```powershell
uv sync --locked
pwsh -File scripts/dev.ps1
pwsh -File scripts/verify.ps1
pwsh -File scripts/build.ps1
```

脚本优先使用 `uv` 命令，也可使用工程内 `.tools/uv-bootstrap/bin/uv.exe`。脚本不自动安装依赖；缺少环境时先执行同步。默认验证排除 `local` 标记测试，`-IncludeLocal` 才包含需要本机游戏输入的测试。构建默认先验证；主 agent 在已验证并固定源码后可用 `-SkipVerify` 进行串行构建。候选目录为 `dist/<版本>/ArknightsUnpacker`，存在时拒绝覆盖。每次构建的工作目录和临时文件位于 `.work/build/<任务 ID>`；失败会返回非零。

HTML 的开发验收入口为 `node scripts/verify-html.cjs --html <导出的HTML路径> --output <证据目录>`，通过真实浏览器检查离线报告。脚本需要本机 Node.js 与 Playwright；已有 Playwright 安装可通过 `NODE_PATH` 指定其 `node_modules` 目录。它们只用于开发验收，不是便携程序或离线 HTML 的运行依赖。

`build-info.json` 记录版本、精确依赖、上游提交与源码文件摘要；`file-manifest.json` 及 `SHA256SUMS.txt` 记录程序包文件摘要。无 Git 时来源如实记录为工作区文件清单。手动修改程序文件后需重新构建并重新验收；不要将预检目录当作正式发行候选。
